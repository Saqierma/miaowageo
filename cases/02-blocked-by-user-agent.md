| 计分项 | 26 |

## 这个案例说明了什么

本项目最有价值的一次发现。抓取器拿到 403，而**同一台检测机上的无头浏览器**（普通浏览器 User-Agent）成功加载了页面。同 IP、同时刻、只差一个 User-Agent——这强烈提示拦截是按 User-Agent 判定的。而 GPTBot / ClaudeBot / PerplexityBot 走的正是「自报 User-Agent」这条路。

## 报告里最要紧的几条

| 判定 | 观测 |
| --- | --- |
| 未通过 | robots.txt 中针对 ClaudeBot 的规则实质为整站不允许抓取：现有的 Allow 规则（如果有的话）未覆盖任何内容路径。影响 Claude 检索。 |
| 需改进 | robots.txt 中针对 Google-Extended 的规则实质为整站不允许抓取：现有的 Allow 规则（如果有的话）未覆盖任何内容路径。影响 Gemini 的 grounding，不影响传统 Google 搜索排名。 |
| 未取得 | 对方返回 HTTP 403，本次未取得内容。静态可读性未测。 |
| 未取得 | Chrome 用户体验报告（CrUX）没有该站点的字段数据。 |

## 决定性的对照

同一台检测机、同一次检测里，**无头浏览器（普通浏览器 User-Agent）成功加载了这个页面**：

| 判定 | 观测 |
| --- | --- |
| 已通过 | 浏览器构建出的可访问性树结构完整，AI 代理能据此理解页面结构。 |
| 已通过 | 累积布局偏移（CLS）实测 0.002。 |

同一个出口 IP、同一时刻，抓取器被 403 拒绝而浏览器进得去——**两者只差一个 User-Agent**。

> 这是强提示，不是证明：我们没有代替 GPTBot 真的访问一次。
> 建议在服务器日志里核对这几个 User-Agent 的实际响应码。
